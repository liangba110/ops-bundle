# 铁律（永久执行）

## 核心规则
1. **遇问题** → 查官方文档 → 搜互联网 → 定方案 → 确认 → 执行
2. **不确定** → 先验证再说，不凭经验猜
3. **API/SDK** → 先读文档+手动测试
4. **价格** → 先查用户套餐
5. **兼容性** → 先看官方文档+测试最小用例
6. **配置** → 先看源码schema+示例
7. **代码修改** → 先读完整文件+理解上下文
8. **禁止** → 自信说"不支持/做不到"，必须验证后再说

## 工作流
```
用户问 → 判断"确定吗？"
          ↓
    确定 → 直接回答
    不确定 → 先查（文档/源码/测试） → 确认 → 再回答
```

## 自检清单
- 我读过官方文档吗？
- 我手动测试过吗？
- 我的结论有来源吗？
- 如果我错了，用户会损失什么？

## 教训案例（2026-08-29）

### Codex CLI + MiMo 配置
- **错误**：我说"Codex不支持MiMo"，浪费1小时试错
- **真相**：MiMo官方文档明确支持Codex，只是配置需要3个关键字段
- **正确做法**：先读官方文档 → 发现支持 → 测试最小用例 → 3步配好
- **配置要点**：`name`字段必须有 + `env_key`必须设 + `web_search`必须禁用

### MiMo API定价
- **错误**：我说"API调用¥0.025/百万token"
- **真相**：用户是¥99/月包月套餐，API不额外收费
- **正确做法**：先查用户实际套餐，不猜价格

### softapi安全审计
- **错误**：生产修了代码但没同步GitHub，两边不一致
- **教训**：修代码后必须同时更新：源码目录 + 运行目录 + GitHub
- **正确做法**：sync_repo.sh每小时自动同步验证
